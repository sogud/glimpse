# Glimpse 原生 macOS 相册分类 Spec

原生 macOS 应用已经有 GlimpseMac target，仍在开发中。本 Spec 只定义原生 PhotoKit 流程，不定义 standalone CLI。CLI 是独立入口，不是 App 的控制客户端；当前功能与发布范围见 [功能说明](functionality.md)，CLI 命令见 [README](../README.md)。

## 目标与边界

在 Apple Photos 全图库、指定相册、日期范围或最近 7/30/90 天范围内，本机视觉模型生成分类建议。默认来源为全图库，默认创建下一批 10 张、可选择最多 100 张；模型仍逐张串行推理。用户在网格中复核后显式写入相册；图片/OCR 不上传云端，不自动删除照片。原生应用最低 macOS 15，需要兼容系统的完整 Xcode。CLI 二进制不依赖这个构建。

只分析静态图片和 Live Photo 的静态图，不分析视频帧、不识别人名、不反向地理编码。不捆绑、下载或自动加载模型；使用用户已经启动并加载视觉模型的 LM Studio 0.4+ 本地服务。原生 App 不依赖 lms 子进程，开始分类前再次检查所选视觉模型实例确实已加载。

## 原生 GUI 行为契约

- 使用纯 AppKit 的 NSWindow、NSTableView、NSCollectionView 和原生菜单，PhotoKit 负责照片访问；不使用 SwiftUI、NSHostingView 或 Web GUI，也不通过 CLI 访问 Photos。原生任务记录与 CLI 独立，界面明确说明不共享进度。
- 新建页显示当前授权范围内的照片数量；有限权限只称为“可访问照片”，不能称为图库总数。未授权或被拒绝时提供权限说明及系统设置入口。
- 选取下一批时，按资源修改日期、模型和方案身份/版本排除已有结果，排除尚未完成任务占用的资源，不重复建立同一批。没有下一批时显示原因，不保存空任务。删除任务会失去该任务的分类进度。
- 创建任务时固定本批资源 ID。暂停、继续或图库新增照片不扩大这批范围；缺失资源从本批移除，修改过的资源重新识别。
- 模型通过 /api/v1/models 区分已下载、视觉能力及 loaded_instances，提供刷新；已下载不等于已加载。服务未连接不等于没有下载模型，界面不得提示重新下载；读取失败显示实际错误及下一步。不从模型名称保证能力，声明支持视觉也不保证实际 runtime 兼容。运行期间不能切换端点，任务使用开始时确定的客户端。
- 进度页显示本批总数、已分析、已有类别、待分类和未分析数量。暂停后旧请求尚未退出时显示“正在暂停”，不能立即启动新请求。
- 复核支持将已有类别明确改为待分类，以及逐张取消写入勾选。非 readyForReview 状态只读，不能拖动、更改类别或批准状态。
- 写入确认列出相册名称与照片数量，以实际批准、非跳过且有类别的记录生成；没有可写入项时禁用按钮。确认之后若复核内容改变，要求重新确认，不写入新内容。
- 分析完成不等于已写入。写入中断保留结果未知状态；“待删除”只是分类建议，不删除照片。

本轮测试入口是上述用户可见的选批、任务进度、复核与确认写入，以及模型 HTTP 边界。使用合成照片身份、隔离存储和本机测试服务器，不以个人 Photos 为测试数据。原生编译由兼容 Xcode 验证，纯逻辑检查不替代真实界面验收。

AppKit 替换保留现有行为和核心逻辑，不保留第二套 SwiftUI 界面。界面检查通过原生控件操作合成任务，验证空状态、类别修改、批准状态和取消确认不会触发写入；检查程序不调用 PhotoKit 或真实模型。照片网格使用系统字体、系统颜色和清楚的方案/分类标签，支持键盘选择、批量改类和详情查看。分类修改或筛选刷新不得让正在加载的缩略图永久停留在占位图。相册映射必须显示任务实际保存的目标，即使该目标不在本次刷新列表中，也不能显示成“本次跳过”；写入时仍需检查实际目标是否可用。窗体关闭后任务可继续运行，菜单栏提供重新打开、暂停和退出。

模型状态字段按 [LM Studio 原生模型列表](https://lmstudio.ai/docs/developer/rest/list) 实现；[OpenAI-compatible 模型列表](https://lmstudio.ai/docs/developer/openai-compat/models) 在开启 JIT 时可能包含未加载模型，因此不能用它判断原生 GUI 的加载状态。不添加旧 REST API 回退或旧格式迁移。

## 分类与复核

- PhotoKit 截图标记选择独立方案；截图可附带本机 Apple Vision OCR。普通照片和截图类别互不混用。
- 分类方案可编辑。任务保存方案快照，类别有稳定 ID、显示名、说明和启用状态。
- 一张图片一次模型推理，只选择一个允许的类别或待分类，附简短理由。无静默降级或第二次请求；拒绝非回环端点和重定向。
- 默认方案包含保守的“待删除”候选类别：只有明显无用或无法阅读的图片才能建议，不能仅因是截图或存在敏感资料就建议删除。默认目标名称为“方案·类别”，防止同名普通照片/截图类别合并；两种方案的待删除候选统一映射到“待删除”。创建任务时复用唯一同名相册；多个同名相册默认跳过，必须在复核映射中显式选择。
- 网格支持查看理由、选择照片、修改类别及目标映射；分析与复核不修改 Photos。
- 每个类别映射到已有相册、新相册或跳过。用户确认后才能创建/添加；空类别不创建相册。

## 任务与持久化

使用一个 SwiftData 任务记录保存来源、方案快照、模型、分类结果、复核、进度和变更。缓存复用必须同时匹配资源 ID、修改日期、模型、分析器版本和方案身份/版本。JPEG 与 OCR 只临时使用，不进入任务记录。

正常状态为 draft → running → paused 或 readyForReview → applying → applied → undone；分析错误可为 failed。App 重启时 running 改为 paused，applying 改为 interrupted，不自动继续或认定成功。

- 暂停只请求取消，旧任务退出前不得继续或启动另一个推理。每次异步调用后、保存结果前检查取消。
- 活动推理、写入及 interrupted 任务不能删除；删除已有任务前说明会丢失复核和撤销记录。
- 写相册按相册逐步进行，每步确认后保存变更；失败或退出保留 interrupted 和已知记录。用户先检查实际 Photos，再明确确认已检查并关闭任务；不得重新运行同一任务的写入或撤销。需要继续整理时创建新任务并明确选择已有目标相册。
- 未确认的写入不能猜成成功，也不能假定已回滚。Photos 整批写入不是原子事务。
- 撤销只移除该任务记录为新增的成员，不删除照片；撤销中断同样保留 unknown，检查后只能关闭，不能用重新 apply 来恢复。没有可靠记录的变更不能自动撤销。创建相册的删除需要另行确认。

当前开发格式不提供旧数据读取、向后兼容或迁移。AppKit 界面替换不改变当前原生存储格式，不重置 Tasks.store。原生任务使用独立的 ~/Library/Application Support/Glimpse/Native/Tasks.store，目录仅当前用户可访问；CLI 和旧原生数据库、旧模型设置均不导入，也不删除。分类方案和模型设置使用 native 前缀的偏好键。无法打开存储时显示实际启动错误，不自动清空数据库。开发与验证使用临时存储，不清空个人记录。

## 原生验收要求

纯逻辑、合成控件检查和 CI 编译不等于真实图库验收。将原生 App 标记为生产可用前还需：

1. 用隔离任务存储及可控 Photos/模型边界验证暂停后立即继续、推理中删除、部分写入、应用退出重启和撤销失败；取消后不得保存旧快照。
2. 在兼容 Xcode 构建实际 UI，检查 interrupted 提示、活动按钮、复核、目标映射、写入与撤销。
3. 在用户另外授权的真实 Photos 样本中验证权限和 iCloud 行为，5 张普通照片 + 5 张截图至少 8 张无需改类别，5 分钟内完成且 UI 可响应。
4. 验证不确认就没有相册变化；确认后只写指定成员，撤销不改变原有成员。
5. 检查请求只到回环地址，临时 JPEG/OCR 不进入持久记录。PhotoKit 请求 iCloud 图片可能使用系统网络。

不包含 App Store、notarization、自动更新、云识图、telemetry 或无人确认的删除。原生包只标为内部预览，不代表上述真实图库与原生 UI 验收已经完成。
