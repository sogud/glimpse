# 功能与发布范围

本次内部开发版发布 standalone macOS CLI，支持 macOS 14+ 的 Apple Silicon。原生 macOS/iOS 不包含在 CLI 安装包中；不能把 CLI 验证结果当成原生应用验收。开发规则见 [AGENTS.md](../AGENTS.md)。

## CLI 验收契约

- 全图库按稳定 Photos ID 分批处理，单批最多检查 10 个项目。视频和未能导出的图片占名额并记录为 skipped；不需要手选。手选入口也记录分类进度。
- 排除 ID 使用本机哈希集合；一次读取图库 ID 后寻找下一批，不逐项通过 Apple Events 查询整个已处理前缀。相册完成前核对本批所有非缺失成员，不只核对新添加项。
- 先检查本机模型服务和已加载模型，再导出图片。每张只发送一次结构化识图请求；端点必须是回环地址且不得跟随重定向。
- 模型响应必须有 category 和非空 reason；category:null 是待分类，缺失 category 是错误，不能算完成分析。
- Photos 临时导出副本，缩小到最长边 1024 px JPEG 后识别；正常退出和错误路径清理副本。强制终止可能留下临时文件。iCloud 原图可能需要下载。
- 导出元数据只包含 ID、尺寸和序号；文件名从实际导出文件读取，制表符或换行不改变资源身份。元数据损坏必须报错，不保存猜测的跳过 ID。
- 分析只保存计划，不修改图库。每项只有一个类别或待分类；模型失败与待分类分别计数。待删除只是一条复核建议。
- 单个计划最多 10 项，资源 ID 最多 512 字节；apply 只读最多 1 MiB 的计划文件。不要手工合并成一个巨大计划，批量应用多个小计划。
- 先保存新的计划，再推进批次状态；已有输出文件不覆盖。进度只保留每个资源的一份结果，不由 classified 推断相册写入。
- 同一用户的分类、retry 和 apply 串行执行，即使 GLIMPSE_HOME 不同也不能并行写同一个 Photos 图库。锁在进程退出后自动释放；另一个写进程在访问 Photos 前报错。
- 单次分析失败后在后续批次重试，失败三次后停止自动重试。retry failed 只重置已失败三次的项目，保留 retryPending 的失败计数；retry skipped 只重置跳过项。两者不删除成功记录。
- apply 完整验证计划，在显示固定相册清单并收到 yes 后才写入 Glimpse 文件夹。只增加成员关系，不移动或删除照片，不提供撤销或自动回滚。
- 每个相册写入前保存 unknown 状态，成功后保存实际 added/existing/missing ID。中断后 apply 同一原始计划跳过 confirmed 相册，未知相册通过检查已有成员继续。已开始的计划不得修改。
- 回执必须完整覆盖计划中的相册资源：confirmed 必须有非空相册 ID 和互不重复的 added/existing/missing 集合；损坏回执不得跳过 Photos 操作或宣称完成。
- 数据采用当前格式，不读旧格式、不迁移。默认目录为 ~/Library/Application Support/Glimpse/CLI；GLIMPSE_HOME 用于隔离。旧个人文件保留，但去重进度不会带入新目录。
- 运行目录必须由当前用户拥有、非软链接且仅当前用户可访问；拒绝已有共享目录，不自动改它的权限。状态、回执与计划文件为 0600。status 只输出计数和相册状态摘要，不输出照片 ID、文件名或分类理由。

命令、状态字段和使用顺序以 [README](../README.md) 为准；安装和运行要求见 [CLI 安装说明](cli-install.md)。

## 原生应用范围

macOS 使用 SwiftUI / AppKit 和 PhotoKit，默认全图库下一批 10 张，可选最多 100 张；已有结果和未完成任务占用的资源不会再次建立任务。任务创建后固定资源，不因继续任务而扩大范围。新建页显示可访问照片数量、服务连接与模型加载状态，并明确原生进度与 CLI 不共享。与 CLI 一样由用户在 LM Studio 启动服务并加载视觉模型，不依赖 lms 子进程。支持可编辑分类方案、OCR、网格复核和目标相册映射。

只能在 readyForReview 修改类别、批准状态和目标，明确改为待分类也会取消批准；写入期间及终态只读。写入确认列出实际相册与数量，无可写入项不允许提交；复核快照变化必须重新确认。任务取消后保留活动句柄直到退出，界面显示正在暂停；活动推理/写入任务不能删除。重启时推理改为 paused，未完成写入或撤销改为 interrupted，要求先检查实际相册，随后只能关闭任务，不能重新 apply 或撤销该任务。逐相册保存已确认新增记录；不得把中断操作标记为完成。

普通照片与截图的默认相册名包含方案名称，“待删除”候选统一使用同一相册，且不提供自动删除照片。创建任务时复用唯一同名相册，同名歧义默认跳过，要求在复核映射中明确选择。原生设计和待完成验收见 [macOS Spec](macos-local-photo-classification-spec.md)。iOS 保留自己的滑动清理流程，与 CLI 状态不共享。

## 验证与限制

运行 `bash scripts/check.sh`：使用合成照片元数据、临时状态、注入的 Photos 命令和本机 HTTP 测试服务，覆盖参数/计划验证、去重、失败计数、retry、跨进程锁、中断回执恢复、20,000 个排除 ID、模型错误前置检查、禁止重定向、一次推理、子进程超时，以及原生纯任务状态和模型协议。

CI 另用完整 Xcode 编译 GlimpseMac。下载的 CLI 不需要 Xcode。用 bash scripts/package-cli.sh vX.Y.Z 生成签名二进制、安装说明和校验和；发布包必须经过独立目录安装检查，且不得包含照片、计划、状态或本机私人路径。

这些检查不验证真实 Photos Automation/PhotoKit、系统授权、iCloud、当前视觉模型准确率、真实图库性能或原生 UI。内部使用时先复核小批计划，再单独确认 apply；不能宣称已经通过无人值守全图库整理或原生生产验收。
